# AI

Omarchy nabízí plnou podporu AI agentů pro programování, ale oblíbence si vyberete sami. Příkazy hlavních agentů jsou připravené k použití a potřebný program se stáhne až při prvním spuštění. Tyto drobné spouštěče spravuje [mise](https://mise.jdx.dev/) v `~/.local/bin/`. Výjimkou je Hermes: nemá takový spouštěč a jeho výběrem se nainstaluje Hermes Desktop, jak vysvětluje sekce _Desktopové aplikace_ níže. Spusťte některého z agentů a na výzvu se přihlaste:

| Příkaz    | Agent                                                            |
|------------|------------------------------------------------------------------|
| `claude`   | [Claude Code](https://code.claude.com/docs/en/overview)          |
| `codex`    | [OpenAI Codex](https://github.com/openai/codex)                  |
| `opencode` | [OpenCode](https://opencode.ai/)                                 |
| `agy`      | [Google Antigravity CLI](https://github.com/google-antigravity/antigravity-cli) |
| `copilot`  | [GitHub Copilot CLI](https://github.com/github/copilot-cli)      |
| `crush`    | [Crush](https://github.com/charmbracelet/crush)                  |
| `grok`     | [Grok Build](https://x.ai/build) od xAI                        |
| `kimi`     | [Kimi Code](https://www.kimi.com/code/docs/en/)                  |
| `pi`       | [Pi od Maria Zechnera](https://github.com/badlogic/pi-mono)        |
| `omp`      | [Oh My Pi](https://github.com/can1357/oh-my-pi)                  |
| `ori`      | [Ori](https://openrouter.ai/docs/guides/ori/harness), prostředí pro spouštění agentů od OpenRouteru |
| `hermes`   | [Hermes](https://hermes-agent.nousresearch.com/), agent od Nous Research  |
| `muse`     | [Muse Code](https://dev.meta.ai), kódovací agent od Meta           |
| `cursor-agent` | [Cursor CLI](https://cursor.com/cli)                         |

`ori` je mezi nimi zvláštní: umožňuje ostatním agentům používat celý katalog modelů OpenRouteru, takže `ori claude`, `ori codex` nebo `ori opencode` spustí tyto agenty na jakémkoliv modelu, na který je nasměrujete, a `ori code` je vlastní agent Ori.

Chcete-li stejným způsobem zabalit další CLI, spusťte `omarchy-mise-install <package> [command-name]`. Zástupné programy jsou udržovány aktuální spolu se vším ostatním, co mise spravuje, když spustíte `omarchy update` (nebo alias `mup`).

`grok` se instaluje prostřednictvím oficiálního balíčku `grok` v mise, stejným způsobem jako `claude` a `codex`. Spusťte `grok`, nebo si ho vyberte pod _Setup > Defaults > Agent_. Přeskočte instalační program `curl | bash` na x.ai. Tato cesta vloží druhou kopii do `~/.grok/bin`, přidá ji na začátek `PATH` a přepíše wrapper od Omarchy.

### Výchozí agent

Svého výchozího agenta si vyberete příkazem `omarchy default agent <name>` nebo pod _Setup > Defaults > Agent_ v nabídce Omarchy Menu (`Super + Space`). Pokud agent ještě není nainstalovaný, jeho výběrem se nejprve nainstaluje. Čerstvě nainstalované Omarchy vás k tomuto výběru vyzve jednorázovým oznámením.

Výběrem Claude se také pokusí nastavit jeho rozšíření prohlížeče pro Chromium, Chrome, Brave, Brave Origin a Edge. Nastavení rozšíření platí pro všechny uživatele a může si vyžádat vaše systémové heslo; zrušení nebo neúspěšná instalace rozšíření Claude přesto vybere a spustí. Restartujte prohlížeč, na výzvu rozšíření povolte a přihlaste se ke Claude, abyste dokončili jeho připojení. Spusťte `/chrome` v Claude a zkontrolujte připojení. Firefox a Zen toto rozšíření nepodporují. Pokud jste Claude měli jako výchozího už před přidáním tohoto nastavení, vyberte ho znovu, aby se rozšíření nainstalovalo.

[Muse Code](https://dev.meta.ai) — `muse` od Meta — používá předinstalovaný zástupný program mise stejně jako ostatní agenti. Jeho výběrem jako výchozího se prostřednictvím HTTP backendu mise nainstaluje oficiální spouštěč od Meta. Spouštěč ověřuje a aktualizuje nativní binární soubor pro váš stroj.

Jakmile si vyberete, `Super + Shift + Ctrl + A` spustí výchozího agenta ve vyhrazeném okně terminálu (nebo zobrazí výběr, pokud jste si ještě nevybrali). Můžete ho také spustit přímo do úkolu příkazem `omarchy agent prompt "Review this project"`. Takto spuštění agenti běží bez dohledu ve svých příslušných režimech, ve kterých se nezastavují, aby se zeptali, takže buďte připraveni na to, že skutečně budou něco dělat! A protože agenti odmítají pamatovat si důvěru pro váš domovský adresář, spuštění z `$HOME` místo toho začíná v `~/Work`.

Existují také zkratky v terminálu: `a` spustí výchozího agenta přímo v aktuálním terminálu, zatímco `c`, `cx` a `cy` spouštějí přímo OpenCode, Claude Code a Codex (opět v jejich režimech automatického schvalování). Změny motivu se synchronizují i do agentů: Claude Code, Pi, OpenCode a Hermes (jakmile ho Omarchy nainstaluje) všechny následují, když přepnete motiv Omarchy.

### Panel agentů

Na horní liště najdete ikonu agentů. Pokud zatím žádného nemáte nastaveného, panel vás provede přihlášením ke Claude, Codex nebo Grok. První nastavený agent se stane výchozím. Panel pak na jednom místě zobrazuje všechna předplatná: agenty a účty s jejich tarify, využití pětihodinových a týdenních limitů i čas do jejich obnovení, případně zbývající předplacený kredit. Přesné procento využití uvidíte po najetí myší. Nad nimi se střídají souhrnné údaje, například počet tokenů za tento týden nebo nejpoužívanější model. V části _Vytvořte něco skvělého_ najdete předpřipravená AI zadání pro vytvoření nového motivu, pluginu nebo aplikace. Úkol dostane váš výchozí agent. Aplikace vznikají stejně jako vlastní aplikace Omarchy Hype, Monologue a Omacut: v C++ a Qt Quick podle AI skillu omarchy-app (sady instrukcí pro agenta). Potřebný kompilátor a součásti Qt jsou už nainstalované. Panel podporuje Claude Code, Codex, Grok, Fireworks a Kimi ihned po instalaci. Kimi zatím hlásí jen limity účtu, nikoli místní statistiky tokenů a AI zadání.

Levé kliknutí na ikonu v liště pro panel, pravé kliknutí pro spuštění vašeho výchozího agenta. Záznamy o využití, které za ním stojí, jsou každých 15 minut regenerovány příkazem `omarchy agent usage-update` a panel dokáže dokonce sloučit využití z vašich ostatních strojů prostřednictvím synchronizované složky. Úplné nastavení najdete v README pod `$OMARCHY_PATH/shell/plugins/agents/`.

### Několik předplatných

Pokud si platíte více než jeden plán Claude, Codex nebo Grok — řekněme osobní Max a pracovní — Omarchy je může nechat všechny přihlášené a pohybovat se mezi nimi. Přidejte předplatné tlačítkem + v panelu agentů, které vás tím provede přímo tam, nebo příkazem `omarchy agent account add claude Work` (nebo `codex`, nebo `grok`). Nainstaluje CLI, pokud chybí. První účet pro poskytovatele se přihlašuje prostřednictvím vašeho běžného prohlížeče, přímo tam, kam CLI vždy kouká. Každý další po něm se přihlašuje prostřednictvím soukromého okna, aby se omylem nevybral účet, ke kterému je váš prohlížeč už přihlášený; přihlaste se tam jako účet, který přidáváte, a nejprve zavřete každé soukromé okno, které už máte otevřené. Kvůli tomu se nikdy neodhlašujte z CLI: odhlášení zruší uložené přihlášení a daný účet by musel být přidán znovu.

Chcete-li zkopírovat přihlášení k předplatným na jiný stroj s Omarchy přes SSH, spusťte `omarchy agent account copy user@laptop`. Odesílatel dodá dočasný přijímač, když cíl žádný nainstalovaný nemá, takže starší stroje s Omarchy mohou přijímat účty bez aktualizace. Nainstalované přijímače mají přednost. Tím se kopírují všechna předplatná Claude, Codex a Grok; přidejte názvy poskytovatelů, abyste je vybrali, jako v `omarchy agent account copy laptop claude`. Názvy účtů a ID příkazů odpovídají zdroji, včetně účtů, které už jsou v cíli. Nesouvisející cílové účty obdrží číselnou příponu, pokud se jejich názvy střetnou, a nastavení, AI skilly, pluginy a historie konverzací zůstávají lokální pro každý stroj.

Existující cílové přihlašovací údaje zůstanou zachovány. U zdrojového účtu, který je tam už přihlášený, se jeho název synchronizuje, aniž by se nahradily jeho přihlašovací údaje; ostatní účty se přidají vedle něj. Chcete-li nahradit uložené přihlašovací údaje pro odpovídající účty, použijte `omarchy agent account copy --replace laptop claude` poté, co v cíli ukončíte relace daného účtu. Čerstvý cíl dostane také aktivní účet zdroje a předvolby pro přepínání; zavedený cíl si zachová své vlastní.

Přihlašovací údaje cestují prostřednictvím SSH a jsou uloženy v soukromých souborech v cíli, takže kopírujte pouze na stroje, kterým důvěřujete. Je to jednorázová kopie, nikoliv průběžná synchronizace. Refresh tokeny Codex může rotovat jiný stroj, čímž zkopírované přihlášení zůstane potřebující obnovu; samostatná přihlášení zůstávají nejspolehlivější volbou pro současné použití na několika strojích. Viz [pokyny Codex k ověřování účtů](https://developers.openai.com/codex/auth/ci-cd-auth).

U každého poskytovatele je aktivní jeden účet. Použijí ho všechny nové relace: `cx`, `cy`, samotné příkazy `claude`, `codex` a `grok`, vše spuštěné přes `omarchy agent` i skripty a editory, které najdou příslušné CLI v `PATH`. Účet přepnete příkazem `omarchy agent account use work` a zpět příkazem `omarchy agent account use main`. V panelu stačí stisknout číslo účtu a pak `Enter`, případně kliknout na jeho tlačítko Použít. Už běžící relace zůstávají na původním účtu. Historie konverzací, nastavení, AI skilly a pluginy jsou společné pro všechny účty. Příkazem `claude --continue` tak můžete ve stejné složce pokračovat v konverzaci i po přepnutí účtu.

S více než jedním účtem panel zobrazuje limity každého účtu vedle sebe, s označeným aktivním. Ve výchozím nastavení vás Omarchy upozorní, když aktivní účet překročí 95 % limitu, a kliknutí na oznámení přepne na účet s největší zbývající rezervou. Najeďte myší na řádek účtu v panelu a klikněte na Autoswitch, které se objeví vedle Use (nebo stiskněte `m`), nebo spusťte `omarchy agent account mode auto`, aby se místo toho přepínal samo; zatímco je zapnuté, Autoswitch zaujme místo Use a opětovné kliknutí na něj se vrátí k oznamování. Přidejte číslo, abyste změnili práh, jako v `omarchy agent account mode auto 90`. Pokud je každý účet nad prahem, dozvíte se o tom jednou, spolu s tím, který účet se uvolní jako první. Zatímco je aktivní účet do 15 bodů od svého prahu (ve výchozím nastavení 80 %), jeho limity se kontrolují každé tři minuty místo každých 15.

`omarchy agent account list` zobrazuje každý účet a jeho nejnovější limity, `omarchy agent account remove work` jeden zapomene a `omarchy agent account rename primary Hey` jeden přejmenuje (nebo klikněte na název účtu v panelu). Tyto příkazy pracují s účty vašeho výchozího agenta; chcete-li dosáhnout na jiného poskytovatele, jmenujte ho nejprve, jako v `omarchy agent account use codex side`. Přihlášení, které jste už měli v `~/.claude` nebo `~/.codex`, je účet _Main_ a zůstává tam, kde je. Účet ponechaný nepoužitý déle než zhruba osm hodin může zobrazovat _Sign-in required_; kliknutím na něj daný účet znovu přihlásíte přímo v panelu, nebo v něm spusťte relaci, což přihlášení obnoví samo. MCP servery, které jste měli, když byl účet přidán, s ním přicházejí, ale ty, které přidáte později příkazem `claude mcp add`, se dostanou pouze k účtu, ve kterém jste je přidali. Claude Desktop a nástroje nakonfigurované s absolutní cestou k binárnímu souboru CLI přepnutí nenásledují. Explicitní `CLAUDE_CONFIG_DIR`, `CODEX_HOME` nebo `GROK_HOME` má před vybraným účtem přednost.

### Diagnostika pádů

Omarchy pomocí systemd-coredump sleduje pády procesů. Při chybě segmentace zobrazí oznámení o pádu. Kliknutím předáte diagnostiku výchozímu agentovi spolu s AI skillem diagnose-crash od Omarchy. Ten agenta provede rozborem výpisu paměti a posouzením, zda má smysl chybu nahlásit vývojářům. Diagnostiku můžete spustit i ručně pro libovolné PID z `coredumpctl list` příkazem `omarchy agent crash <pid>`.

Sledování je ve výchozím nastavení zapnuté. Vypněte ho pod _Trigger > Toggle > Crash Capture_ (nebo příkazem `omarchy toggle crash-capture`) a oznámení přestanou; `omarchy agent crash <pid>` ručně stále funguje.

Pády lze také umlčet jeden program po druhém, což je to, co vám diagnóza na konci nabídne. `omarchy crash mute hyprland` zastaví oznámení pouze pro daný program, `omarchy crash mute hyprland off` je přivede zpět a `omarchy crash mute` o samotě vypíše, co jste umlčeli. Bere cestu k binárnímu souboru stejně ochotně jako jeho název, takže `omarchy crash mute /usr/bin/hyprland` udělá totéž. Název s mezerou dejte do uvozovek, jako v `omarchy crash mute 'Some App'`. Všechno ostatní stále oznamuje a umlčený program stále padá — tohle skrývá připomínku, nic to neopravuje.

### Desktopové aplikace

Nabídka _Install > AI_ nese také několik grafických AI aplikací: desktopovou aplikaci ChatGPT, desktopovou aplikaci Claude (linuxová beta od Anthropic s kartami Chat, Cowork a Claude Code), Grok Bot pro chatování s modely xAI, Hermes Desktop, OpenClaw a desktopovou aplikaci Perplexity. Grok Bot je desktopová chatovací aplikace. Kódovací agent je příkaz `grok`.

U Hermes Desktop je důležité vědět, že Omarchy používá jedinou instalaci Hermes, kterou zajišťuje tato aplikace. Příkaz `hermes`, který spouští výchozí agent, patří právě k ní. Výběr Hermes jako výchozího agenta nainstaluje totéž co _Install > AI_: balíček aplikace a běhové prostředí Hermes v `~/.hermes`. To připraví vlastní instalátor Hermes a první instalace trvá několik minut. Terminálový příkaz `hermes`, výchozí agent i aplikace používají stejné běhové prostředí. Aktualizuje se příkazem `hermes update` a nemusí čekat na nové vydání Omarchy. Při instalaci získá také motiv Omarchy pod názvem `omarchy`, takže jeho rozhraní reaguje na přepínání motivů v systému. Pokud chcete jiný vzhled, vyberte ho v nastavení Appearance v Hermes nebo příkazem `/skin`. Omarchy vaši volbu zachová. Odebrání přes _Remove > AI_ nejprve zavře Hermes včetně služby gateway a odstraní i jeho běhové prostředí. Chaty, vzpomínky a AI skilly, které si Hermes vytvořil, zůstanou zachované. Instalační program se zeptá, zda chcete smazat i tato data a nastavení připojení; výchozí odpověď je ne.

Grafické rozhraní OpenClaw se jmenuje Control UI. Otevírá se jako webová aplikace a komunikuje s místní službou gateway. OpenClaw je uložený v `~/.openclaw` a aktualizuje se sám: použijte tlačítko „Update Gateway“ v Control UI nebo příkaz `openclaw update`. Služba gateway se poté restartuje s novou verzí. Omarchy určuje jen výchozí verzi pro novou instalaci. Odebrání přes _Remove > AI_ odstraní aplikaci i službu gateway a zeptá se, zda smazat také `~/.openclaw`. Tento adresář obsahuje chaty, přihlašovací údaje, samotný OpenClaw i běhové prostředí stahovaných pluginů. Ve výchozím nastavení se zachová, takže při opětovné instalaci můžete navázat na původní nastavení.

### Lokální LLM

Omarchy doporučuje dva způsoby spouštění lokálních modelů LLM: LM Studio a Ollama. LM Studio poskytuje GUI rozhraní pro hledání modelů s otevřenými váhami, jejich instalaci a spouštění. Je to skvělý způsob, jak snadno začít. Ollama nabízí CLI pro podobné dělání. Pokud jste ale u lokálních modelů noví, začal bych s LM Studio. Obě můžete nainstalovat pod _Install > AI_ v Omarchy Menu.

### AI skill pro Omarchy

AI skilly jsou sady instrukcí, které agentům vysvětlují, jak pracovat s konkrétními nástroji. Omarchy obsahuje vlastní AI skill pro úpravy systému: od nastavení Hyprlandu přes úpravy lišty až po vytvoření nového motivu. Symbolické odkazy ho zpřístupňují v adresářích AI skillů pro Claude Code (`~/.claude/skills`), Codex (`~/.codex/skills`), Pi (`~/.pi/agent/skills`), Antigravity (`~/.gemini/config/skills`) a Hermes (`~/.hermes/skills` a každý `~/.hermes/profiles/*/skills`), i v obecném umístění `~/.agents/skills`. Většina prostředí pro práci s agenty ho tak najde automaticky.

Tento AI skill zatím považujte za experimentální. Různé modely si s ním poradí různě. Začněte v režimu plánování, abyste nejprve zjistili, co chce agent změnit. A buďte připraveni změny vrátit, případně spustit `omarchy reinstall configs`, pokud agent všechno podělá.
